Rustman scripting language

Pre-request and test scripts run on rustman-engine, a small interpreted language written in Rust for Rustman. It is not JavaScript: there is no pm.* API, no Node builtins and no require/import. The language is small so an LLM can write a correct script from a plain-English request. This page lists everything it has; anything not listed here does not exist.

When scripts run

Every HTTP request has a pre-request script and a test script in its Scripts tab. Settings → General → Global scripts holds one more pair that runs for every request. Scripts don't run for WebSocket connections. One send goes like this:

  • The global pre-request script runs, then the request's own.
  • The request's {{variables}} are filled in, so a value set_env just wrote is the one that is sent.
  • The response arrives. The global test script runs, then the request's own.

A blank script is skipped. The request's own script sees what the global one did: environment changes through env(), and the headers and body it set through header(), headers() and body(). Test results and print output from both land in the response's Tests tab, in order; the output goes to its Console.

Test scripts also run when no response came back, after a timeout or a refused connection. response.status is then 0 and the body is empty.

If you sync collections with Git, the global scripts are committed with them. Read secrets with env() rather than typing them into a global script.

rustman-cli run runs the same scripts, plus the app's global scripts when the collection is one saved in the app. What one request's scripts write with set_env, the next request reads; the CLI doesn't save it. --no-scripts turns scripts off.

body() and url() return the text as written, so a {{variable}} in them is not filled in. For a GraphQL body, body() and set_body work on the query.

set_header and set_body change only the request being sent, never what is saved in the editor, and they do nothing in a test script. set_body works on JSON, Text and GraphQL bodies. A header the Auth tab sends (Authorization, Cookie or the API key header) replaces any header with the same name.

The Content-Type follows the body type unless a header row or set_header sets one: JSON and GraphQL bodies go out as application/json, text bodies as text/plain.

set_env writes to the environment that was active when you pressed Send and saves it, the same as editing it by hand. In a pre-request script the change applies to the request it runs for: a {{token}} set there is the one that is sent. With no active environment, set_env does nothing.

When a script fails

A script stops at its first error: a syntax error, or a runtime error such as an unknown function or comparing a string with <. None of that script's effects apply, and the scripts after it in the same phase don't run. Effects of a script that already finished stay: a global script's set_env is kept even when the request's own script then fails.

  • A failing pre-request script stops the send. The error shows in place of the response.
  • A failing test script leaves the response in place and shows the error in the Tests tab.

The error names the script, as in Global pre-request script error: …. Syntax errors carry a line number; runtime errors don't.

Syntax

Statements

let name = <expr>
if <expr> { <statements> }
if <expr> { <statements> } else { <statements> }
<expr>

A trailing ; is optional. There is no else if: put another if inside the else { } block. There are no loops and no user-defined functions.

Comments and literals

  • // rest of line. No block comments.
  • Numbers: 42, 3.14, all floating point. There is no unary minus, so -5 is a syntax error; write 0 - 5.
  • Strings: "double-quoted", with the escapes \n \t \" \\. Any other escape is an error. A string may span lines.
  • true, false and null.

Variables

let x = <expr> binds x for the rest of the script, and another let x replaces it. There is no assignment without let. Scope is flat: a name bound inside an if block is still bound after it. A name that was never bound reads as null, not an error, so a misspelled name gives null.

Operators, highest to lowest precedence

#OperatorsNotes
1.field / .method() / fn(args)Field access and calls
2!Logical not (prefix)
3+ -Numbers add and subtract. + with a non-number joins text; - with one is an error.
4< > <= >=Numbers only; anything else is a runtime error
5== !=Different types are never equal. Lists are equal when their elements are, in order; objects when their fields are, in any order.
6&&Logical and, short-circuits, gives true or false
7||Logical or, short-circuits, gives true or false

Parentheses group as usual. There is no *, / or %.

Joining text

+ on two numbers adds them. Otherwise both sides are turned into text and joined, so "Bearer " + token and "count: " + 3 both work. A list or object becomes a readable form such as {id: 7}, not JSON; use json_stringify when you need JSON.

Field access

value.field reads a field of an object from json_parse(...), jwt_decode(...), headers() or response.json(). A missing field, or a field of something that isn't an object, is null, not an error. env(), header() and cookie() differ on purpose: a missing value is "", so the usual check is != "".

The response object (test scripts only)

  • response.status: the HTTP status code, a number. 0 when no response came back.
  • response.json(): the body parsed as JSON; null if it isn't valid JSON.
  • response.text(): the body as a string.
  • response.contains("..."): short for contains(response.text(), "...").

There is no response.headers. In a test script header(name) and headers() read the response's headers. Their names are lowercase, and a header sent more than once, such as Set-Cookie, comes back as one value with a newline between the copies. In a pre-request script response is null.

Built-in functions

An argument shown as string must be a string. Anything else, null included, is a runtime error, so check a value with != null before passing it on.

FunctionSignatureNotes
env(name)(string) → stringA variable of the active environment. "" if unset, not null.
set_env(name, value)(string, any) → nullWrites a variable to the environment that was active at Send, and saves it. Lists and objects are stored as JSON, anything else as its text form.
header(name)(string) → stringCase-insensitive; the first header with that name. Request headers in a pre-request script, response headers in a test script. "" if absent.
headers()() → objectEvery header, with the same request/response split as header().
set_header(name, value)(string, any) → nullSets a header on the outgoing request. Pre-request scripts only. The value converts like set_env, so set_header("X-User-Detail", claims.payload) sends JSON.
cookie(name)(string) → stringCase-insensitive lookup in the request's Cookie string. "" if absent.
body()() → stringThe request body: as written, or as set_body left it. In a test script, the body that was sent. response.text() is what came back.
set_body(value)(any) → nullReplaces the JSON or Text body, or the GraphQL query, for this send. Pre-request scripts only. Converts like set_env.
url()() → stringThe request URL as typed, {{variables}} not filled in.
test(name, condition)(string, any) → nullA pass in the Tests tab when condition is truthy, a fail otherwise.
print(value)(any) → nullA line in the Tests tab's Console. Lists and objects print as JSON.
base64_encode(s)(string) → stringStandard alphabet, with padding.
base64_decode(s)(string) → stringStandard, or URL-safe without padding. null if invalid or not UTF-8.
jwt_decode(token)(string) → objectReads the claims without checking the signature. Accepts a bare token or "Bearer <token>". Returns { header, payload }; payload is null when the token is malformed.
contains(haystack, needle)(any, any) → boolSubstring test on a string, membership test on a list, key test on an object. Case-sensitive. Also written haystack.contains(needle). A non-string needle is matched by its text, so contains(body(), 404) works. false, never an error, on a null, bool or number haystack.
json_parse(s)(string) → anyParses JSON text. null on invalid JSON.
json_stringify(value)(any) → stringReal JSON, with quoted keys and strings: the inverse of json_parse.
aes_encrypt(text, key)(string, string) → stringAES-256-GCM, keyed by the SHA-256 hash of key, so any string works. Returns base64(nonce || ciphertext), with a new random nonce each call.
aes_decrypt(text, key)(string, string) → stringReverses aes_encrypt. null if the key is wrong or the input is malformed.

Truthiness, used by if, !, &&, || and test: null, false, 0, "" and an empty list are falsy. Every other value is truthy, including every object.

aes_encrypt and aes_decrypt round-trip with each other, but the framing (SHA-256 key derivation, nonce || ciphertext) is this engine's own. It is not guaranteed to match another system's AES-GCM. If an API dictates its own key derivation or nonce layout, these functions won't fit it as they are.

Limits

  • Nesting: 256 levels. Blocks, parentheses, call arguments, ! and operator chains such as a + b + c all count. Deeper nesting is a syntax error.
  • Strings: 16 MiB. A script that would build a longer string with +, base64_encode, json_stringify or aes_encrypt stops with a runtime error.

With no loops and no functions, every script ends. Scripts can't read files or make network calls.

Worked examples

Inject a bearer token, only if one is set

// pre-request script
let token = env("access_token")
if token != "" {
    set_header("Authorization", "Bearer " + token)
}

Set a variable the same request uses

// pre-request script; the URL is {{base_url}}/users/{{user_id}}
let claims = jwt_decode(env("access_token"))
set_env("user_id", claims.payload.sub)

Variables are filled in after the pre-request scripts, so the URL is sent with the user_id the script just wrote.

Save a token from the response

// test script
let token = response.json().access_token
test("got a token", token != null)
if token != null {
    set_env("access_token", token)
    set_env("user_id", jwt_decode(token).payload.sub)
}

Assert on the JSON response body

let body = response.json()
test("id is 7", body.id == 7)
test("name matches", body.name == "ferris")

Compare a whole list or object

let body = response.json()
test("tags are a, b", body.tags == json_parse("[\"a\", \"b\"]"))
test("owner matches", body.owner == json_parse("{\"name\": \"ferris\", \"id\": 7}"))

There are no list or object literals, so json_parse builds the expected value. Lists must match in order; object fields may come in any order.

Range check with if/else

let status = response.status
if status >= 200 && status < 300 {
    test("ok range", true)
} else {
    test("ok range", false)
}

Assert on a keyword in the response

When the body isn't JSON, test the text. The last two lines are the same test written two ways: 

test("no stack trace leaked", !contains(response.text(), "panicked at"))
test("says expired", response.text().contains("expired"))
test("says expired", response.contains("expired"))

Matching is case-sensitive, so "Expired" does not match "expired". The language can't change a string's case, so when the server's capitalization varies, pick a substring that doesn't, like "xpired".

Branch on a header, then check a role is in a list

if contains(header("Content-Type"), "json") {
    let body = response.json()
    test("user is an admin", contains(body.roles, "admin"))
    test("payload carries a roles key", contains(body, "roles"))
} else {
    test("json response", false)
}

On a list contains tests membership, and on an object it tests whether a key is present.

Check the server set a cookie

test("has a session cookie", contains(header("Set-Cookie"), "session_id="))

cookie() reads the request's own Cookie string, so it can't see what the server set. The response's Set-Cookie header can.

Forward a JWT cookie's claims as a header

A session JWT lives in a cookie, and the backend wants the decoded user details in one header. 

// pre-request script
let claims = jwt_decode(cookie("accessToken"))
set_header("X-User-Detail", claims.payload)

set_header turns the object into JSON, the same as json_stringify(claims.payload). To send one field, pass that field: set_header("X-User-Id", claims.payload.sub).

Print what a request sent, from its test script

print(url())
print(body())
print(headers())   // in a test script, the response's headers

Encrypt the outgoing body, decrypt the response to assert on it

// pre-request script
set_body(aes_encrypt(body(), env("body_key")))
// test script
let plaintext = aes_decrypt(response.text(), env("body_key"))
test("response decrypts", plaintext != null)
if plaintext != null {
    test("order id present", json_parse(plaintext).order_id != null)
}

What this language does not have

No loops, no user-defined functions, no else if, no *, / or %, no [ ] indexing, no list or object literals (build a constant one with json_parse), no try/catch (an error ends the script), no string slicing, no case conversion and no regex: contains is the only pattern matching. A task that needs one of these doesn't fit in a script.

Prompt for an LLM

Copy the block below into an LLM, add your request at the end, and paste the script it writes into the Scripts tab. 

You write scripts in Rustman's scripting language: a small custom language
(not JavaScript, no pm.* API). Use only what is listed below. Nothing else
exists, and invented syntax or functions fail.

STATEMENTS: `let x = <expr>`, `if <expr> { ... }`, `if <expr> { ... } else { ... }`,
or a bare expression. `;` is optional. No `else if` (nest an `if` inside
`else { }`), no loops, no user-defined functions, no assignment without `let`.

LITERALS: numbers (no negative literals: write `0 - 5`), "double-quoted
strings" (\n \t \" \\ escapes), true, false, null. No list or object literals:
build a constant one with json_parse("[...]").

OPERATORS, low to high precedence: || , && , == != , < > <= >= (numbers only) ,
+ - (numbers add; + with a non-number joins text) , ! (prefix not) ,
.field / .method() / call(...). No * / %. No [ ] indexing.
== compares lists and objects by content. Different types are never equal.

NAMES: a name never bound with `let` is null. A missing field, or a field of a
non-object, is null.

COMMENTS: `// rest of line`.

BUILT-IN FUNCTIONS:
  env(name) -> string                    ("" if unset)
  set_env(name, value)                   (writes the active environment; in a
                                           pre-request script, {{name}} in the
                                           same request uses the new value)
  header(name) -> string                 ("" if absent; case-insensitive; request
                                           headers pre-request, response headers
                                           in a test script)
  headers() -> object                    (every header, same split as header())
  set_header(name, value)                (pre-request scripts only)
  cookie(name) -> string                 ("" if absent; the request's Cookie
                                           string, not the response's Set-Cookie)
  body() -> string                       (the request body as written; in a test
                                           script, the body that was sent)
  set_body(value)                        (pre-request only; replaces a JSON or
                                           Text body, or the GraphQL query)
  url() -> string                        (the request URL as typed)
  test(name, condition)                  (passes when condition is truthy)
  print(value)                           (debug log, no assertion)
  base64_encode(s) / base64_decode(s)    (decode gives null if invalid)
  jwt_decode(token) -> {header, payload}  (no signature check; accepts a bare
                                           token or "Bearer <token>"; payload is
                                           null if the token is malformed)
  contains(haystack, needle) -> bool     (substring in a string, membership in a
                                           list, key in an object; case-sensitive.
                                           Also written haystack.contains(needle))
  json_parse(s) -> value                 (null on invalid JSON)
  json_stringify(value) -> string
  aes_encrypt(text, key) / aes_decrypt(text, key)   (AES-256-GCM, key is any
                                           string, SHA-256 derived,
                                           base64(nonce||ciphertext); decrypt
                                           gives null on failure)

RESPONSE (test scripts only; null in a pre-request script):
  response.status (number; 0 if no response came back), response.json() (null
  if not JSON), response.text(), response.contains(needle).
  To check a cookie the server set: contains(header("Set-Cookie"), "name=").

Arguments that are names or text (env, header, cookie, set_env/set_header
names, base64_*, jwt_decode, json_parse, aes_*) must be strings: null is a
runtime error, so check with `!= null` first. set_env, set_header, set_body
and print accept any value: objects and lists become JSON, anything else its
plain text form.

CONVENTIONS: env()/header()/cookie() return "" for a missing value: check with
`!= ""`. A missing JSON field is null: check with `!= null`.

LIMITS: nesting at most 256 levels deep; strings at most 16 MiB.

There's a GLOBAL pre-request/test script pair that runs before every
request's own scripts. Mention it only if the request clearly applies to
every request.

Output ONLY the script: no explanation, no markdown code fences, no JS
syntax, no pm.* API.

My request: <describe what you want the script to do>
